# XARVIS: notes for Claude

Personal on-device AI assistant for Android, owned by Rex (developer credit: Sajjad Raja). Rex isn't an Android developer: explain in plain language, pick sensible defaults, do the work yourself, and give a short summary of what works and what's next.

## How development works now

- There is no local machine with adb. Code changes go to `main` on GitHub; `.github/workflows/build.yml` runs the unit tests, builds `app-debug.apk` (artifact **XARVIS-v1.0.<run>-apk**, JDK 21) and checks its signature. A green CI run is the build check.
- Every push to main is also published as a GitHub release `v1.0.<run>` with `XARVIS.apk`; install links: **S22 https://github.com/rexraja89-oss/XARVISS/releases/latest/download/XARVIS.apk**, **benco https://github.com/rexraja89-oss/XARVISS/releases/latest/download/XARVIS-benco.apk**. Two flavors: `full` and `benco`; the benco build drops CALL_PHONE because the benco refuses to install sideloaded apps with it ("package appears to be invalid"; found with test builds, see test-perms release), so calls there open the dialer (direct download in Chrome, no zip, no sign-in). The benco's Files app failed to extract artifact zips.
- Rex installs each new APK himself. Links tapped in the Claude app open in an in-app browser (or the GitHub app) whose download never reaches Downloads, so he downloaded twice (then shared to Chrome). From v1.0.46 XARVIS checks GitHub's latest release every 30 min and (from v1.0.48) whenever the screen opens, since the always-on service keeps the process alive (`update/Updates.kt`) and shows an **UPDATE TO vX** button that opens this phone's APK (benco or full) directly in Chrome: download once, Open, Update. Tell him exactly what to test after installing, since nobody else can run it on the device.
- Unit tests (`app/src/test`, plain JVM logic: tool-line parsing, link commands, the prompt, identity guard, contact matching) run in CI before the build. Add a test when adding a tool. If CI fails, compiler and test errors show as a "Build errors" annotation on the check run (readable via the GitHub API even when raw logs aren't).
- `./gradlew assembleDebug` needs an Android SDK with platform 37; if the environment has none, rely on CI.

## Versions and signing (so updates install as upgrades)

- versionCode = GitHub run number, versionName = `1.0.<run>`; the screen shows `v1.0.<run>` at the start of the AI MODEL line.
- Every CI build is signed with one permanent key from the **XARVIS_KEYSTORE** repo secret (base64 PKCS12, alias `xarvis`, password `xarvis-signing-key`). CI fails if a build signed with the secret doesn't match `.github/signing-cert-sha256.txt`. Without the secret, CI warns and falls back to a throwaway debug key, and that APK can't upgrade a permanently signed install.
- Before the permanent key, every CI build had a different random debug key, so updates often failed to install ("App not installed") while Rex thought they had: that's why fixes seemed not to work. Switching keys needs one uninstall; memories come back by re-pairing with the other phone (memory sync).
- Never commit the keystore. Don't use session credentials to set repo secrets; Rex adds the secret himself.

## The AI model file

- Gemma lives in the app's own folder (`Android/data/com.xarvis.ai/files/models/`), so **uninstalling XARVIS deletes it**. With no model, the screen shows a "DOWNLOAD AI MODEL" button (`llm/ModelDownloader.kt`): Android's DownloadManager fetches `gemma-4-E2B-it.litertlm` (~2.4 GB, Wi-Fi or mobile data, not roaming: Rex chose mobile data) from huggingface.co/litert-community/gemma-4-E2B-it-litert-lm to a `.download` file, renames it when complete, then loads it. huggingface.co is blocked from the Claude sandbox, so this can't be tested here.

## How XARVIS answers

- Every message goes to Gemma (`agent/XarvisAgent.kt`); on a phone without the model, a linked phone's Gemma answers (`remoteChat`) and the tools still run on the phone that was typed on. There is no keyword matcher; Rex asked for Gemma to decide.
- Gemma's tools, called with a line like `TOOL: contact Atiq`: `time`, `remember <fact>`, `open <app>`, `contact <name>`, `call <name|number>`, `whatsapp <name>: <text>`, `sms <name>: <text>`, `location`, `battery`, `bluetooth` (status) / `bluetooth on|off`, `wifi on|off`, `flashlight on|off`, `alarm <time>`, `timer <duration>`, `search <words>`. Readers are `tools/LocationTool`, `BatteryTool`, `BluetoothTool`; actions are `workflow/PhoneActions`; alarm/timer text is read by `agent/TimeSpecs`. `map [place]` opens Maps. `ask <app>: <text>` shares text into an app (ChatGPT opens with the question typed; Rex taps send; else copy+open). `find <app>: <words>` searches inside an app (its ACTION_SEARCH, a search URL for LinkedIn/Drive/GitHub/YouTube, else opens it and copies the words to paste). App names go through `device/AppNames.kt` (Rex's aliases: "chat gpt", "YT studio", "files", "calender"...; web apps: payslip/Olive = https://altrad.olivehrms.com, a guess from his payslip download host). XARVIS can't tap inside other apps (no accessibility service); for multi-step tasks it opens the app and says what Rex must do. Calls: placed directly only when Rex's own message asks ("call Atiq", "Ali ko call karo": `XarvisAgent.forUser`, which also turns Gemma's `contact` into a call then); a call Gemma chooses by itself opens the dialer. If Gemma talks about a tool instead of using it ("I can use the location tool if you ask"), `skippedTool` triggers one nudge asking for the TOOL line. Safety otherwise:, WhatsApp/SMS open prefilled (user taps Send); Android won't let apps toggle Wi-Fi/Bluetooth off, so those open the system switch. `agent/ToolCalls.kt` reads them (tolerant of markdown, `ACTION:`, `<>`, "'s number"); `workflow/WorkflowEngine.kt` runs them. Tool results are shown directly, not sent back to Gemma (one pass, and Gemma can't ignore the data).
- Chat memory (Rex asked for ChatGPT-like memory): every exchange is saved (`MemorySystem.logInteraction`, JSON in the `interaction` category; older entries are "command => reply"). Chats work like ChatGPT's (Rex asked): each opening of XARVIS starts a new chat (`XarvisAgent.chatId`, saved as "c" in each exchange; entries from before chats are grouped by day). The ☰ menu / left-edge swipe (`ui/ChatParts.ChatList`) lists chats titled by their first message, with NEW CHAT; opening one shows it and continues it. The system prompt carries that chat's last 8 exchanges (≤2500 chars), or in a new chat the topics of the 5 latest chats (`XarvisAgent.history`, refreshed only when the conversation restarts, so the prompt stays stable); a linked phone sends its own in the `chat` op's `history`. `TOOL: recall <words>` searches all saved chats (blank = latest 12) and gives them back to Gemma to answer. The header's MEM count is facts only.
- `memories` lists every remembered fact (`MemorySync.facts`). `XarvisAgent.mistakenTime`: Gemma once answered "do you remember... from the time I built you" with the clock, so a `time` call when Rex's message isn't asking for the time/date gets one nudge, and is dropped if Gemma insists.
- `contact` searches this phone (`tools/ContactFinder.kt`, `ContactsDirectory` matching) and, if nobody matches, linked phones (link op `contacts`).
- Personality (Rex asked for humour): JARVIS-like dry British wit, "sir" now and then, never robotic; taught with a prompt line plus three few-shot examples.
- Voice (`voice/Voice.kt`): Google's TTS engine (`com.google.android.tts`) when installed, because the S22's default Samsung engine gave only a female voice (Rex: "sounds like Friday"); then with a British male voice (Google's rjs/gbd/gbb en-GB voices first), pitch 0.88: JARVIS *style*; we don't clone Paul Bettany's real voice. The 🎤 button (shown instead of SEND when nothing is typed) uses Android's speech-recognizer activity (RecognizerIntent, no mic permission needed); replies to the mic are spoken. The 🔊/🔇 switch at the end of the version line reads every reply aloud (prefs "settings"). STOP also stops speech.
- Hands-free voice (Rex asked for waking by voice with the screen off): **A** `VoiceActivity` ("XARVIS Voice"): opens listening, shows over the lock screen, handles ACTION_ASSIST (so XARVIS can be picked as the phone's digital assistant: the assistant gesture/button opens it) and has its own launcher icon (activity-alias `VoiceLauncher`, for Samsung's side-button double-press "Open app"). **B** `service/WakeWordService` (foreground, type microphone, RECORD_AUDIO): openWakeWord's offline "Hey Jarvis" models (`assets/wakeword/*.tflite`, CC BY-NC-SA, personal use) run in `voice/WakeWordDetector` on TensorFlow Lite (mel -> embedding -> score, 80 ms chunks, threshold 0.5; the pipeline was checked in Python: "hey jarvis" 0.997, other speech 0, "hey xarvis" only 0.075, so the word is Jarvis). On a hit: beep, `voice/VoiceCommand` (SpeechRecognizer, no UI), `core.submit(spoken = true)`; the mic is released while XARVIS listens/thinks/talks (`core.busy()`) and while the in-app mic or the voice screen uses it (`WakeWord.paused`). The ☰ menu has the switch and "Make XARVIS the phone's assistant". Android only allows background mic use when started with XARVIS on screen, so `MainActivity.onResume` (re)starts it; after a reboot Rex must open XARVIS once. The APK is arm64-only (abiFilters) since both phones and the model need it.
- The only exact commands are for linking phones (`agent/LinkCommands`): `pair with <device>`, `code <6 digits>`, `devices`, `unlink <device>`. The pairing code is a security check, so it isn't left to Gemma.
- The system prompt is short on purpose: identity ("You are XARVIS, a personal AI assistant created by Rex..."), the tools with one few-shot example each, then all saved memories under "Facts you know:" (capped at 3000 chars, newest kept). It's rebuilt before every call and `LocalLlm.chat` restarts the conversation when it changes. Each message also gets `IDENTITY_REMINDER`, and `fixIdentity` replaces "developed by Google" replies. Facts aren't repeated per message, to save context.

## Photos and linking from anywhere

- Photos: the 📷 button uses Android's photo picker; `llm/PhotoPrep` shrinks the photo to ≤1024 px (upright JPEG in cache), and `LocalLlm.chatWithImage` sends `Contents.of(Content.ImageFile, Content.Text)`. The engine opens with `visionBackend = CPU` (not GPU: S22 driver), falling back to text-only if the model can't. Only the phone with the model (S22) analyses photos. `TOOL: lookup <words>` makes XARVIS read Wikipedia (`tools/WebLookup`, REST search + page summary) and ask Gemma again with the facts (`XarvisAgent.withLookups`); `search` only opens Google for Rex and Gemma never sees results (it used to invent "I couldn't find any movie"). CI names the APK `XARVIS-v1.0.<run>.apk`: a leftover app-debug.apk in Downloads made the benco's file manager fail to extract ("Error unknown").
- On the benco (no model), a photo goes to the S22 over the link (op `photo`: base64 JPEG + question + facts); the S22 looks at it in that phone's side conversation (`LocalLlm.chatAsWithImage`) and tools in the reply run on the benco.
- The input row is "+" · text box · SEND (STOP while XARVIS writes). "+" opens a pull-up menu (`ui/ChatParts.AttachSheet`, a list of `AttachOption`s: add new attachable capabilities there) with Photo (lens, `ic_photo_lens.png`) and File (folder, `ic_file.png`), pictures Rex chose. STOP cancels the reply's coroutine (keeps the text so far, adds "(stopped)", runs no tools) and calls LiteRT-LM's `cancelProcess` by reflection when it exists.
- Chat bubbles have no "YOU"/"XARVIS" labels; each has an avatar instead. Rex's is `ic_avatar_rex.png` (his photo, close-up, background removed to black, which he asked for). XARVIS's is the app icon split into `ic_xarvis_core.png` (the "XARVIS" text) and `ic_xarvis_ring.png` (the particle ring): while it's thinking, the ring turns and breathes and three procedural particle strands twist around it (`XarvisAvatar`); when the reply is done it freezes in place.
- While Gemma writes a file, the chat shows "Writing name.pdf… (N words)" instead of the file's text (`FileBlocks.preview`). `TOOL: convert <pdf|docx|xlsx|txt>` turns the last attached file into that format without Gemma rewriting it.
- Files Rex sends (folder button, Android's file picker, no storage permission): `files/DocumentReader` reads PDF (`files/PdfText`, our own small reader: Flate/ASCII85 streams, object streams, ToUnicode maps, form XObjects; first 40 pages; scanned or password-locked PDFs have no readable text), .docx/.xlsx/.pptx (`files/OfficeFiles`, zip XML read with regexes), and text files (txt/csv/html/json...). Old .doc/.xls aren't readable. The agent sends as much as fits (`LocalLlm.documentChars`: 12,000 chars at 8192 tokens, 5,000 at 4096; 8,000 to a linked phone) with Rex's question.
- Files XARVIS makes: Gemma writes `FILE: name.ext` ... `END FILE` (`files/FileBlocks`, tolerant of markdown and a missing END). `files/FileStore` saves to Downloads/XARVIS through MediaStore: .pdf drawn with `PdfDocument` (A4, headings/bullets/wrapping), .docx and .xlsx as minimal OOXML zips (`OfficeFiles.docx/xlsx`; Excel content is CSV or a markdown table), anything else as text. No .pptx writer. The reply shows each file with OPEN and SHARE. `TOOL: files <words>` finds files XARVIS made before (its own index in prefs "files"); XARVIS can't search other files on the phone.
- The context is 8192 tokens when the model file accepts it (falls back to 4096), replies up to 1536 tokens (long enough for a file). When a message fails (usually a full context), `LocalLlm` restarts the conversation and tries once more.
- Away from home Wi-Fi: Tailscale. Each request carries this phone's Tailscale address (`tailnet`, a 100.64.0.0/10 address on a VPN network); peers store it as `Peer.tailnetHost` and try it when the Wi-Fi address fails. Rex installs Tailscale on both phones with one account; the phones must talk once (same Wi-Fi) after that to learn each other's Tailscale address.

## Things learned the hard way

- LiteRT-LM's GPU path corrupts text on the S22 (fp16 on a 2022 Adreno driver): obviously with the `-gpu` model build, subtly (odd mangled words) with the general build. `LocalLlm.calibrate()` compares GPU and CPU answers once per model file and picked **CPU** (~15 tokens/s). Don't switch the S22 to GPU; don't reintroduce the `-gpu` model (it can't run on CPU).
- v1.0.55 ("Hey Jarvis") was refused by the S22 ("package appears to be invalid"). Test builds (releases test-nomic, test-recordonly, test-fgsmiconly, test-mictype) showed RECORD_AUDIO alone installs, FOREGROUND_SERVICE_MICROPHONE alone installs, but **both together are refused** (likely a spyware heuristic: background mic + contacts + location + calls + boot). So XARVIS declares RECORD_AUDIO and the microphone service type but not FOREGROUND_SERVICE_MICROPHONE, which Android only checks from 14; the S22 is on 13 and "Hey Jarvis" works there (verified by Rex, screen off). On Android 14+ `WakeWord.available` is false and the switch says so. Rex says "Hey XARVIS", which the model barely hears (0.075): tell him to say Jarvis with a J. Just after a reboot the model takes about a minute to load; `XarvisAgent.brainReady` waits (up to 3 min) instead of answering "no AI model on this phone" (that happened to a wake-word question). If a future phone needs it, the plan is a separate tiny "XARVIS Ears" app with only mic permissions.
- Adding pdfbox-android (with its BouncyCastle crypto jars, +13 MB) made the S22 refuse v1.0.42 with "package appears to be invalid", though the APK was well-formed and correctly signed. Don't add big crypto/PDF libraries; the benco showed the same message for CALL_PHONE. Before adding any dependency, weigh that the phones' installers judge the whole package.
- LiteRT-LM 0.17.1 has no fp32 activation option (it exists only on their main branch).
- Gemma E2B ignores instructions as the prompt grows (it answered "I don't have access to your location" with the location in its prompt). Keep the prompt short, prefer few-shot examples, and show tool data directly.
- When a fix "doesn't work", first check the version on the phone's screen. An update restarts XARVIS and opens a new chat.
- Anything Android 13 related: the notification permission prompt arrives after the service's first notification, so `MainActivity` re-posts it once granted.

## Architecture

Entry points: `XarvisApp`/`XarvisCore` (process-wide core), `agent/XarvisAgent.kt`, `llm/LocalLlm.kt`, `net/DeviceLink.kt` (mDNS + ECDH pairing + AES-GCM; reconnects when Wi-Fi returns), `memory/MemorySync.kt`, `service/XarvisService.kt` (always-on foreground service; opening the app turns it back on). Runtime permissions go through `tools/PermissionGate`, which MainActivity attaches to.
