## How development works now

- There is no local machine with adb. Code changes go to `main` on GitHub; `.github/workflows/build.yml` runs the unit tests, builds `app-debug.apk` (artifact **XARVIS-v1.0.<run>-apk**, JDK 21) and checks its signature. A green CI run is the build check.
- Every push to main is also published as a GitHub release `v1.0.<run>` with `XARVIS.apk`; install links: **S22 https://github.com/rexraja89-oss/XARVISS/releases/latest/download/XARVIS.apk**, **benco https://github.com/rexraja89-oss/XARVISS/releases/latest/download/XARVIS-benco.apk**. Two flavors: `full` and `benco`; the benco build drops CALL_PHONE because the benco refuses to install sideloaded apps with it ("package appears to be invalid"; found with test builds, see test-perms release), so calls there open the dialer (direct download in Chrome, no zip, no sign-in). The benco's Files app failed to extract artifact zips.
- **Small updates — XARVIS Updater (12 Nov 2026; Rex: "fed up with massive data consumption", "play safe, don't touch what works"):** XARVIS.apk is ~107 MB (engines 57 MB: own-voice/onnxruntime 32, LiteRT-LM 22, TFLite 3.5; dex 39 MB — debug builds, never shrunk; models 9 MB; everything stored uncompressed) but a release changes ~1–3 MB of it (v1.0.259 → v1.0.261: 2.3 MB changed). **XARVIS itself is untouched**: a separate `:updater` app (`com.xarvis.updater`, **XARVIS-Updater.apk**, INTERNET + REQUEST_INSTALL_PACKAGES only, plain Views + coroutines; the install permission is kept out of XARVIS, where with Accessibility + camera it would risk "package appears to be invalid") lists XARVIS (S22/benco build by CALL_PHONE), XARVIS Remote and itself. **Patches** (`.github/scripts/make_patches.py`, format "XVPATCH1" = bsdiff4 1.4.2's blocks with zlib instead of bzip2, control triples int64 BE) are made by **`.github/workflows/patches.yml`**, a separate workflow (`workflow_run` after "Build XARVIS APK" succeeds on a main push, or `workflow_dispatch` with a tag) so it can never block or change a release: from the last 4 releases (S22) / 6 (benco) to the new one, each checked by rebuilding with bsdiff's C code, skipped if > 60% of the full file; then `patches.json` {version, files{name:{sha256,size}} for XARVIS/benco/Remote/Updater, patches[{file, from, fromSha256, asset, size, sha256}]} is uploaded last. ## Versions and signing (so updates install as upgrades)

- versionCode = GitHub run number, versionName = `1.0.<run>`; the screen shows `v1.0.<run>` at the start of the AI MODEL line.
- Every CI build is signed with one permanent key from the **XARVIS_KEYSTORE** repo secret (base64 PKCS12, alias `xarvis`, password `xarvis-signing-key`). CI fails if a build signed with the secret doesn't match `.github/signing-cert-sha256.txt`. Without the secret, CI warns and falls back to a throwaway debug key, and that APK can't upgrade a permanently signed install.
- Before the permanent key, every CI build had a different random debug key, so updates often failed to install ("App not installed") while Rex thought they had: that's why fixes seemed not to work. Switching keys needs one uninstall; memories come back by re-pairing with the other phone (memory sync).
- Never commit the keystore. Don't use session credentials to set repo secrets; Rex adds the secret himself.

## Emotion & emergency ("hear me, help me") (Rex asked, 28 Oct 2026)

Rex asked XARVIS to respond with human-like emotion and, in distress, to place an emergency call handsfree. **Not testable from the sandbox (needs the phone + a real call); logic covered by `EmergencyTest`/`EmotionTest`.**

- **Emergency calling** (`agent/Emergency.kt`): recognises an explicit emergency-call request — a call/connect/need word **plus** a named service — and maps it to the right number for the phone's country (network ISO → SIM → locale; `XarvisAgent.countryIso`/`XarvisCore.deviceCountry`). UAE 999/998/997 (police/ambulance/fire), India 100/102/101, US/CA 911, AU 000, else **112** (universal GSM). `Emergency.detect` is called first in `XarvisAgent.handle` (before reminders), returning `Step.EmergencyCall(number, label)` → `PhoneActions.callNumber` which dials directly (ACTION_CALL; falls back to ACTION_DIAL without the CALL permission — e.g. the benco) and tries handsfree. **Ungated on purpose** (`PolicyRules.categoryOf` → null): no "Ask me" card in a crisis, which is why the trigger must be unmistakable (a plain mention like "the police came" never dials). The spoken confirmation is calm: "Stay calm, sir. Calling the police now (999)…". It's always spoken aloud even if typed.
- **Handsfree audio** (`workflow/CallAudio.kt`, permission `MODIFY_AUDIO_SETTINGS`): after dialing, routes to a Bluetooth headset if one is connected (`setCommunicationDevice`/SCO), else the loudspeaker. **Best-effort** — a cellular call's route is ultimately the system's, and a BT calling headset is routed to automatically anyway; the message tells Rex to tap speaker if it doesn't switch. The reply says where audio went ("You're on your Bluetooth earpiece / speaker").
- **Emotion-aware replies** (`agent/Emotion.kt`): a light heuristic (English + Hinglish + emoji) reads the tone of Rex's message — DISTRESS / ANXIOUS / SAD / FRUSTRATED / EXCITED / JOY / NEUTRAL (most-urgent first). It colours (a) the **words**: a short note is prepended to the brain's prompt (`emotionalPrompt`, e.g. "Rex sounds distressed — be calm, reassuring, no jokes"); and (b) the **voice**: `Voice.speak(text, pitchScale, rateScale)` tilts pitch/pace subtly (calmer/slower for distress, brighter/faster for joy), applied in `XarvisCore.submit` via `Emotion.pitchScale/rateScale`. Emergencies always use the calm (DISTRESS) delivery.
- **Hearing him:** uses the existing "Hey Jarvis" wake word (works on the S22, Android 13) — no new mic infra (that risks the install). So the flow is: "Hey Jarvis" → "I'm in a situation, call the police" → calm confirmation + the call, handsfree.

## Things learned the hard way

- Android silently ignores `startActivity` from an app in the background (no exception), so XARVIS once said "Opening LinkedIn" and nothing opened: a slow reply had arrived after Rex switched away. `workflow/LaunchNotice` checks `inForeground()` (process importance FOREGROUND); when XARVIS isn't in front, `WorkflowEngine.backgroundNote` still tries the launch, posts a heads-up "Tap to open X" notification (always allowed) and says so. Used by `LaunchApp` and `openUrl`. Opening apps never goes through XARVIS Hands (Hands is only imo/WhatsApp calls).

- LiteRT-LM's GPU path corrupts text on the S22 (fp16 on a 2022 Adreno driver): obviously with the `-gpu` model build, subtly (odd mangled words) with the general build. `LocalLlm.calibrate()` compares GPU and CPU answers once per model file and picked **CPU** (~15 tokens/s). Don't switch the S22 to GPU; don't reintroduce the `-gpu` model (it can't run on CPU).
- v1.0.55 ("Hey Jarvis") was refused by the S22 ("package appears to be invalid"). Test builds (releases test-nomic, test-recordonly, test-fgsmiconly, test-mictype) showed RECORD_AUDIO alone installs, FOREGROUND_SERVICE_MICROPHONE alone installs, but **both together are refused** (likely a spyware heuristic: background mic + contacts + location + calls + boot).
